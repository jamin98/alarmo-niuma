# M5Stack Core2 屏幕端

Core2（含 v1.1 / v1.3，BMI270 或 MPU6886 都行）的屏幕正好是 320×240，和 hub 渲染的画面一样大。固件只做几件事：连 WiFi 后连上 hub 的 `/frame.stream` 一直收画面——hub 有新帧就推一条增量帧，只含和上一帧相比变了的 16×16 小块（RGB565 + 行程压缩，平均每帧几 KB 到二十几 KB），不用解 JPEG、没变的地方不重画；收数据在 core 0、画图在 core 1 同时进行，hub 每推一帧都等 Core2 收下再推下一帧，所以不会积压延迟；把按键、触摸、滑动、摇一摇、录音变成 hub 的请求；用振动和扬声器给抽鞭子加反馈。**不需要 USB 串口协议，也不需要 Alarmo 的 AES key。**

| 操作 | 作用 |
|---|---|
| 屏幕下方左键 | 一键鼓励（老板发大饼 + 群里发「大家辛苦了」） |
| 屏幕下方中键 | 点一下 = 显示 / 隐藏聊天记录（切换 hub 的「显示聊天内容」）；在聊天记录 / 额度页里是回到工位 |
| 按住屏幕下方中键 | 按住期间显示历史聊天记录（同时在屏幕上上下滑动可以翻页），松手回到工位 |
| 屏幕下方右键 | 点一下 = 换肤；**按住 2 秒 = 设置** |
| 屏幕上上下滑动 | 转滚轮：进聊天记录、翻页 |
| 点一下屏幕上的某只牛马 | 点名：老板跑过去盯着它，并私聊它一句（`/api/poke`） |
| 点一下顶上橙色的「待确认」 | 打开 bot 问你的问题和选项；点一个选项 = 替你在 Grok Bot 里选上，点卡片外面 = 关掉 |
| 按住某只牛马 / 按住「我」 | 说话私聊它 / 发到群里：用 Core2 自带的麦克风录（屏幕右上角显示 REC），松手把录音传给 hub，由 Grok Bot 听写成文字发出去；最长 60 秒。跑 Grok Bot 的电脑要装虚拟麦克风，见主 README |
| 摇一摇设备 | 抽鞭子（往群里发催进度的话），同时振动 + 啪的一声；要来回用力甩几下才算，碰一下、放桌上不会触发 |

按键触发时会「嘀」一声：固件每几毫秒读一次按键和触摸，读到就先响，请求在后台发给 hub，发请求时画面照常刷新。左键按下就触发；中键要分「点一下」和「按住 0.4 秒」，右键要分「点一下」和「按住 2 秒」，所以这两个键点一下是松手时才触发。

网络差的时候：发按键一直用同一个连接（不用每次重新建）；同一种操作上一下还没发到 hub，再按会提示「网络慢，上一下还在发…」而不重复发；按下超过 2 秒还没发出去的直接丢掉并提示「网络太慢，刚才的操作没发出去」——不会出现连按几次换肤、过一会儿才一下下连着换的情况。

## 编译和烧录

```bash
pip install platformio           # 或用 VS Code 的 PlatformIO 插件
cd m5core2
pio run -t upload                # Core2 用 USB-C 接电脑
pio device monitor               # 看日志（可选）
```

- 第一次编译会下载 ESP32 工具链（几百 MB），需要一点时间。Windows 认不出串口时装 WCH 的 CH9102 驱动。
- **WiFi、hub 地址、口令都在屏幕上设置**，不用改代码、不用重新编译，见下一节。

## 在屏幕上设置

第一次开机（还没设过 WiFi）会直接进入设置界面；以后随时**按住右键 2 秒**进入；连不上 WiFi 或 hub 时，点一下屏幕也能进入。

| 界面 | 怎么用 |
|---|---|
| 设置首页 | 五行：WiFi、WiFi 密码、已保存的 WiFi、hub 地址、hub 口令，点哪行改哪行；底部「取消」「保存并连接」（实体键：左 = 取消，右 = 保存） |
| 选 WiFi | 自动扫描附近的网络，按信号强弱排列，带锁的是有密码的，`*` 是当前用的，标「已保存」的是连过的；点一下选中：连过的直接用存好的密码，没连过的有密码会接着弹出键盘。第一行「手动输入 WiFi 名」用于隐藏网络。底部（或实体键左 / 中 / 右）：上一页 / 重新扫描 / 下一页 |
| 已保存的 WiFi | 连上过的 WiFi 列表（最多 10 个，最近连上的在最前面）：点一个切过去；「删除」点两次删掉（马上生效） |
| 屏幕键盘 | 小写、大写、符号三套键位：「大写」切换大小写（只管一个字母）、「#+=」切到符号、「删除」退格、「OK」确定；左上角「< 取消」放弃这次修改。实体键：左 = 取消、中 = 删除、右 = 确定 |

- hub 地址填 Core2 能访问到的地址，如 `http://192.168.1.100:8765`（hub 启动时会打印本机 IP；hub 所在电脑的防火墙要放行 8765）。忘了写 `http://` 会自动补上。
- hub 口令就是 `hub/config.toml` 里的 `[server] token`；hub 没设口令就留空。
- Core2 只支持 **2.4 GHz** WiFi。
- 设置存在 Core2 的闪存（NVS）里，断电、重新烧录同一个固件都还在；保存后马上用新设置重连。
- **连上过的 WiFi 都会自动记住**。开机或断线时先试上次用的那个，连不上就扫描附近、按信号强弱依次试其他连过的 WiFi——把 Core2 从家里带到公司不用重新设置。
- 扫描 WiFi 时会先断开当前连接（正在连接时 ESP32 扫不了）；扫描失败标题会显示错误码，点「重新扫描」再试。没保存就取消的话，退出后会自动用原来的设置重连。

**出厂默认值（可选）**：想让新烧的 Core2 一开机就用某组设置，可以 `cp include/config.example.h include/niuma_config.h` 再改里面的 `WIFI_SSID` 等，重新编译烧录。只有在 Core2 里还没存过设置时才会用这些值；`niuma_config.h` 在 `.gitignore` 里，没有它也能编译。

## 调参

在 `include/niuma_config.h`（没有就复制 `config.example.h`）：`BRIGHTNESS`（背光）、`SHAKE_G`（摇一摇要甩多用力，默认 2.5g，不想要就写 99）、`SHAKE_HITS`（1.2 秒内要甩几下，默认 3，越大越不容易误触发）。这几项改了要重新编译。

## 排错

| 屏幕显示 | 原因 |
|---|---|
| 「连接 WiFi…」一直转 | WiFi 名或密码不对，或者是 5 GHz 网络；点屏幕进设置重新选 |
| 「hub 连不上」 | hub 没运行 / hub 地址不对 / 防火墙拦了 8765 / 不在同一网段；点屏幕进设置改地址 |
| 画面正常，但按键后提示 `Bad token` | hub 口令和 `hub/config.toml` 的 `token` 不一致；按住右键 2 秒进设置改 |
| 帧率低 | 先确认 hub 的 `[device] fps` 是 20。Core2 每 3 秒把帧率、下载耗时、画图耗时、每帧大小、WiFi 信号报给 hub，打开 `http://<hub>:8765/api/state` 看 `core2` 那一项就知道卡在哪：`ver` 是固件版本，`wait_ms` 是等 hub 推下一帧，`recv_ms` 是收一帧的数据（大说明 WiFi 慢，信号 `rssi` 低于 -75 就算差），`draw_ms` 是画一帧；`neon` 主题每帧变化最多 |
